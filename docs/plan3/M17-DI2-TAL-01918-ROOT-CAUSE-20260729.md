# M17-DI2 / TAL-01918 — Completed-Bar Close Mutation

Status: read-only diagnosis complete. No product code edited.

## Root Cause

Completed display bars can be mutated by same-symbol multichart replay current-price synchronization.

Primary write sites:

- `chart v 1.4/chart/chart.js` — `resolveEffectiveCurrentPrice(visible)`, in the multichart embed branch, writes `last.c = live`, then expands `last.h` / `last.l`.
- `chart v 1.4/chart/modules/replay-system.js` — `_applyCanonicalReplayMarkFromDetail(detail)` writes `last.c = mark`, then expands `last.h` / `last.l`.
- Fallback site: `chart v 1.4/chart/multichart-prod/panel-cmd-bridge.js` — `applyCanonicalReplayMarkToPanel(ch, mark)` performs the same `last.c/h/l` writes if the panel replay system helper is unavailable.

## Mutation Path

1. A multichart host panel is replaying a symbol.
2. A same-symbol embed/panel receives or resolves the host canonical replay mark.
3. Rendering/current-price code calls `resolveEffectiveCurrentPrice(...)`, or replay sync calls `_applyCanonicalReplayMarkFromDetail(...)`.
4. Those paths are meant to align the current price label / forming replay mark.
5. They write the host mark into `chart.data[chart.data.length - 1]`.
6. If the panel has no active forming candle at that moment, that `last` bar is an already completed display bar. Its close and possibly high/low are mutated after close.

The write is especially dangerous because it sits in a read/render path: simply resolving the effective current price can alter historical OHLC.
