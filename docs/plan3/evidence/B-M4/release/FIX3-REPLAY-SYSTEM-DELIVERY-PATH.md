## Residual risks

1. **Inert `?v=` on test host** — confirmed again 2026-07-28: identical sha across query variants. Stamp moves the **cache key**; post-push proof must be **byte-identity** (sha256 of body), not “URL now says bNN”.
2. **Stale design shell** — `/chart/talaria-design/live/` still advertises `b12` while primary shells are `b75`. `bump-dist-v9-cache` stamps `talaria-design/live/index.html` (source) and dist-v9, **not** `homepage/public/chart/talaria-design/live/index.html`. Clients that hit that URL can keep requesting `?v=20260723b12` for up to `max-age=3600` after a push that only advances dist-v9’s stamp.
3. **Nginx 1h TTL** — even with a new stamp, old stamp URLs remain cacheable for an hour if still requested.
4. **Auto-increment behind live** — building without an explicit ahead-of-live `CHART_BUILD_ID` can stamp `b62` while users/edges still hold `b75`-keyed or older URLs.
5. **No module-contract preflight** — nothing in-repo fails the image build solely because module content changed while a forgotten shell kept an old id, beyond checkpoint `matchAllCacheIds` on the **listed** shells (design homepage twin is outside that list).
